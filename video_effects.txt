Looking at how Deforum implements motion effects, here's how to integrate them into your pipeline:

## Deforum's Approach

Deforum applies transformations **before** the diffusion step:

```
1. Take previous frame
2. Apply geometric transform (zoom/rotate/pan)
3. Feed transformed image to img2img
4. Diffusion fills edges/missing areas
5. Save as new frame
```

The key insight: transformations create "missing" or "stretched" areas that diffusion naturally fills in.

## Integration Points in Your Pipeline

You have **two places** to apply transformations:

### Option 1: Transform Keyframes Only (Recommended)

Apply transformations during **PASS 1** (keyframe generation), then interpolation automatically handles the in-between motion:

```python
# In _video_animator.py, modify PASS 1:

from _src.frame_transformer import FrameTransformer, TransformConfig

transform_config = TransformConfig(
    zoom_per_frame=1.02,      # 2% zoom per frame
    angle_per_frame=0.5,      # 0.5° rotation per frame
    translation_x=2,          # 2px pan right per frame
    translation_y=0
)
transformer = FrameTransformer(transform_config)

# PASS 1: Generate keyframes
for i, frame_num in enumerate(keyframe_nums):
    if i == 0:
        # First frame: txt2img
        current_image = generator.generate_from_text(...)
    else:
        # Transform previous keyframe BEFORE diffusion
        transformed = transformer.transform(current_image, frame_num)
        
        # Then run img2img on transformed image
        current_image = generator.generate_from_image(
            init_image=transformed,  # ← Transformed, not original
            strength=0.6,
            ...
        )
```

**Why this works:**
- Keyframes get motion from transformations + diffusion filling
- Interpolation automatically creates smooth motion between keyframes
- **Benefit:** Fewer transformations needed (only on keyframes)

### Option 2: Transform All Frames (Higher Quality)

Apply transformations to **both keyframes AND interpolated frames**:

```python
# After PASS 2 (interpolation), add PASS 3:

# PASS 3: Apply transformations to ALL frames
all_frames = []
for frame_num in range(total_frames):
    frame = load_frame(frame_num)
    transformed = transformer.transform(frame, frame_num)
    all_frames.append(transformed)
```

**Why this works:**
- Each frame gets precise transformation
- No accumulated drift
- **Benefit:** Maximum motion control, smoother

**Trade-off:** More computation, but transforms are fast (< 0.1s per frame)

## Implementation Plan

### 1. Create `frame_transformer.py`

```python
from dataclasses import dataclass
from PIL import Image
import cv2
import numpy as np

@dataclass
class TransformConfig:
    zoom_per_frame: float = 1.0      # 1.02 = 2% zoom per frame
    angle_per_frame: float = 0.0     # degrees
    translation_x: float = 0.0       # pixels per frame
    translation_y: float = 0.0
    
class FrameTransformer:
    def __init__(self, config: TransformConfig):
        self.config = config
        
    def transform(self, image: Image.Image, frame_num: int) -> Image.Image:
        """Apply cumulative transformations based on frame number"""
        
        # Convert to numpy
        img_array = np.array(image)
        h, w = img_array.shape[:2]
        center = (w // 2, h // 2)
        
        # Calculate cumulative transforms
        total_zoom = self.config.zoom_per_frame ** frame_num
        total_angle = self.config.angle_per_frame * frame_num
        total_tx = self.config.translation_x * frame_num
        total_ty = self.config.translation_y * frame_num
        
        # Build transformation matrix
        # 1. Zoom + Rotate around center
        M_zoom_rotate = cv2.getRotationMatrix2D(
            center, 
            total_angle, 
            total_zoom
        )
        
        # 2. Add translation
        M_zoom_rotate[0, 2] += total_tx
        M_zoom_rotate[1, 2] += total_ty
        
        # Apply transformation
        transformed = cv2.warpAffine(
            img_array, 
            M_zoom_rotate, 
            (w, h),
            borderMode=cv2.BORDER_REPLICATE  # Fill edges
        )
        
        return Image.fromarray(transformed)
```

### 2. Modify `_video_animator.py`

Add transformation support to `VideoAnimationConfig`:

@dataclass
class VideoAnimationConfig:

Then integrate in PASS 1:

```python
def generate_animation(self):
    # ... setup code ...
    
    # NEW: Setup transformer if enabled
    if self.config.use_transforms:
        from _src.frame_transformer import FrameTransformer, TransformConfig
        transform_config = TransformConfig(
            zoom_per_frame=self.config.zoom_per_frame,
            angle_per_frame=self.config.angle_per_frame,
            translation_x=self.config.translation_x,
            translation_y=self.config.translation_y

        transformer = FrameTransformer(transform_config)
    
    # PASS 1: Generate keyframes
    for i, frame_num in enumerate(keyframe_nums):
        if i == 0:
            current_image = self.generator.generate_from_text(...)
        else:
            # NEW: Transform before img2img

                current_image = transformer.transform(current_image, frame_num)
            
            current_image = self.generator.generate_from_image(
                init_image=current_image,
                ...
            )
```

## Recommended Approach

**Start with Option 1** (transform keyframes only):
1. Simpler to implement
2. Interpolation handles smooth motion automatically
3. Fast (transforms only on keyframes)
4. Natural-looking results

**Use Option 2** (transform all frames) if:
- You need precise motion control
- You see motion artifacts in interpolated frames
- You want maximum quality for final output

## Key Advantages

1. **Works with interpolation:** Transforms on keyframes = interpolation preserves motion
2. **Fast transforms:** OpenCV transformations are < 0.1s (vs 3s for diffusion)
3. **Flexible:** Easy to add music-driven transforms (zoom on beats)
4. **Deforum-compatible:** Same approach as Deforum
